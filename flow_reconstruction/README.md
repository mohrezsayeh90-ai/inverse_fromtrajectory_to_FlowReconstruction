# بازسازی جریان از مسیر دو ذره

این پوشه یک **حل‌کنندهٔ معکوس آزمایشی** دارد که از وزن آموزش‌دیدهٔ اپراتور جریان استفاده می‌کند. به هر جفت مسیر جدید، پروفایل ورودی و سرعت میانگینی را نسبت می‌دهد که با حرکت ذرات، همواری ورودی و معادلات جریان سازگارتر باشد. وزن‌های DeepONet تغییر نمی‌کنند؛ پارامترهای ورودی برای همان مشاهده بهینه می‌شوند. بنابراین این روش یک forward-pass آنیِ شبکهٔ معکوسِ جداگانه نیست و برای هر جفت مسیر به حل بهینه‌سازی نیاز دارد.

**محدودیت فعلی:** مدل جریانِ مبنا هنوز همهٔ معیارهای پذیرش را پاس نکرده است. دو مسیر نیز تضمین تعیین یکتای کل جریان را نمی‌دهند. خروجی باید به‌عنوان یک تخمینِ مشروط به مدل و prior خوانده شود. تطبیق عالی مسیرها ممکن است با خطای میدان در نواحی دیگر همراه باشد؛ مثال‌های عددی این موضوع را گزارش می‌کنند.

## آنچه از قبل در گیت‌هاب محفوظ است

[ممیزی قابل اجرا](../scripts/verify_reproducibility.py) تمام ۵۱ فایل بستهٔ ران ۱۰۰هزارگامی، وزن آخرین و بهترین مدل، حالت Adam و RNG، ۱۷ فایل سورسِ جاسازی‌شده در نوت‌بوک اجرای اصلی، شش مرجع و ۱۹۲ فایل آرشیو قبلی را بررسی می‌کند. [گزارش ممیزی](../reports/REPRODUCIBILITY_AUDIT.json)، [خروجی‌های اصلی](../reports/experiments/pressure_long/output/) و [کد اجرای کگل](../notebooks/training/pressure_long/) موجودند. ذخیره‌شدن فایل‌ها به معنی تأیید دقت مدل نیست.

```bash
python -m scripts.verify_reproducibility
```

## فرض‌های فیزیکی و واحدها

کانال همان `0≤x/H≤5` و `0≤y/H≤1` است. جریان پایا، ورودی محوری، دیواره‌ها بدون لغزش و اثر ذرات بر سیال صفر است. تنها نیروی ذره، درگ استوکس است:

```text
dq/dt = w
dw/dt = [U(q)-w]/St
St = tau_p * U_ref/H
tau_p = rho_p * d_p^2/(18*mu)
```

تمام CSVها بی‌بعد هستند: مختصات با H، زمان با `H/U_ref` و سرعت پرتاب با `U_ref` تقسیم می‌شوند. زمان پاسخ استوکس برای هر ذره و سرعت اولیهٔ برداری آن معلوم فرض می‌شود. **صرف شکل هندسی مسیر بدون زمان‌بندی کافی نیست.** شکل ذره کروی و میدان گرانش/برخورد/نیروهای دیگر حذف شده‌اند. برای ذرهٔ واقعی باید شرط `Re_particle=d_p*|U-w|/nu <<1` نیز برقرار باشد؛ سرعت پرتاب زیاد این شرط را خودکار تضمین نمی‌کند. مثال یک آزمایش ایده‌آل ذرهٔ نقطه‌ای با St معلوم است، نه اعتبارسنجی یک ماده یا اندازهٔ ذرهٔ مشخص.

ویسکوزیته معلوم فرض می‌شود؛ `reference_reynolds=U_ref*H/nu`. سرعت میانگین نامعلوم A تخمین زده می‌شود و مدل منجمد در `Re=A*reference_reynolds` فراخوانی می‌شود. خروجی در واحد مرجع عبارت است از `U=A*u_operator` و `p=A²*p_operator`. حدود A باید Re را در بازهٔ آموزش ۱۰ تا ۱۰۰ نگه دارند. برای سرعت میانگین معلوم می‌توان دو حد A را یکسان داد. فشار از اپراتور جریان می‌آید؛ قانون درگ استوکس فشار را مستقیماً مشاهده نمی‌کند.

پرتاب دقیق از گوشه با سرعت رو به داخل پشتیبانی می‌شود؛ خروج ذره از کانال، مسیر را متوقف می‌کند. برخورد و بازتاب دیواره شبیه‌سازی نمی‌شوند.

## استفاده با مسیرهای خودتان

در ریشهٔ مخزن، Python 3.12 و کتابخانه‌های [محیط CPU آزموده‌شده](../requirements-cpu-tested.txt) قابل استفاده‌اند:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-cpu-tested.txt
```

هر مسیر یک CSV مستقل دارد، با زمان‌های صعودی؛ تعداد نمونه‌ها و فاصله‌های زمانی دو ذره لازم نیست یکسان باشند:

```csv
t,x,y
0,0,1
0.01,0.05,0.99
...
```

این فقط طرح قالب است؛ فایل واقعی باید حداقل چهار نمونه داشته باشد. فایل JSON ورودی مثلاً:

```json
{
  "units": "nondimensional",
  "tracks": [
    {"name": "upper_left", "csv": "particle1.csv", "initial_position": [0,1], "initial_velocity": [6,-1.2], "stokes_time": 0.42},
    {"name": "lower_right", "csv": "particle2.csv", "initial_position": [5,0], "initial_velocity": [-6,1.2], "stokes_time": 0.42}
  ],
  "inverse": {
    "reference_reynolds": 55,
    "mean_speed_bounds": [0.5,1.5],
    "profile_points": 65,
    "position_scale": 0.001,
    "smoothness": 0.00001,
    "physics_weight": 0.02,
    "starts": 3,
    "max_iterations": 400
  }
}
```

مسیر CSVها نسبت به محل همین JSON خوانده می‌شود. اولین نمونه باید همان نقطهٔ پرتاب معلوم باشد. نقطه و سرعت اولیهٔ مثال، رو به مرکز هندسی کانال هستند؛ سرعت واقعی ذره سپس زیر اثر سیال تغییر می‌کند.

```bash
python -m flow_reconstruction.reconstruct \
  --problem my_tracks/problem.json \
  --checkpoint models/candidates/pressure_long/checkpoint.npz \
  --allow-unvalidated \
  --output runs/my_reconstruction
```

پرچم `--allow-unvalidated` استفادهٔ آزمایشی از وزن فعلی را صریح می‌کند. بدون آن، وزنِ فاقد گزارش پذیرش منطبق پذیرفته نمی‌شود. API:

```python
from flow_reconstruction.io import read_problem
from flow_reconstruction.inverse import FlowReconstructor
tracks, config, _ = read_problem("my_tracks/problem.json")
model = FlowReconstructor("models/candidates/pressure_long/checkpoint.npz",
                          config, allow_unvalidated=True)
result = model.fit(tracks)
```

## روش حل و حدود تعمیم

به‌جای مشتق دومِ مسیر پرنویز، از هویت انتگرالی دقیق معادلهٔ ذره استفاده می‌شود:

```text
q(t) = q0 + St*w0*[1-exp(-(t-t0)/St)]
     + integral_t0^t [1-exp(-(t-s)/St)] * U(q(s)) ds
```

سرعت سیال در نقاط بین نمونه‌های مشاهده، با quadrature گاوس خوانده می‌شود. انتگرال روی مسیر مشاهده‌شده بسته می‌شود؛ بعد از استنتاج، حل مستقل `solve_ivp` روی **مسیرِ پیش‌بینی‌شدهٔ خود ذره** انجام می‌شود. گزارشِ خطای forward ODE جلوی اشتباه‌گرفتن خطای کوچک انتگرالی با بازسازی صحیح مسیر را می‌گیرد. زیادکردن تعداد گره‌های quadrature جای نمونه‌برداری زمانی کافی از مسیر را نمی‌گیرد.

ورودی به شکل spline کاملِ گره‌ای با تعداد قابل تنظیم مدل می‌شود. مقدارهای گره‌ها نسبت به سهموی با log-amplitude تغییر می‌کنند، نرمال‌سازی میانگین با انتگرال دقیق spline انجام می‌شود و سرعت میانگین جداگانه تخمین زده می‌شود. هیچ انتخاب از بانک جواب یا پروژکشن چهارمودی وجود ندارد. تعداد پیش‌فرض ۶۵ گره، **تفکیک عددی و prior** است؛ برای ورودی پُرنوسان می‌توان `profile_points` را افزایش داد و حساسیت به prior را سنجید. این افزایش به‌تنهایی اطلاعات مشاهده یا دقتِ اپراتور مبنا را بیشتر نمی‌کند. نسخهٔ فعلی prior پروفایل غیرمنفی دارد و برگشت جریان را تخمین نمی‌زند.

تابع هدف شامل خطای انتگرالی موقعیت، انرژی انحنای خود پروفایل، prior کوچکِ شکل/سرعت و باقیماندهٔ NS روی نقاط ثابتِ مستقل از مسیر است. این نقاط، دادهٔ حل‌شده یا target میدان ندارند. وزن‌های prior و فیزیک در JSON ثبت می‌شوند؛ با تغییرشان تخمین می‌تواند تغییر کند. بخش‌های مشاهده‌نشدهٔ سیال از اطلاعات مدل و prior پر می‌شود و از مشاهدهٔ مستقیم نتیجه نشده است.

چند شروع، جواب‌های جایگزین می‌دهند. طیف تکین Jacobianِ **داده فقط، بدون prior و فیزیک اضافه‌شده** نیز ذخیره می‌شود. رتبه به پارامترگذاری و آستانه وابسته است و اثبات یکتایی نیست. دامنهٔ جواب‌های چند شروع هم confidence interval کالیبره‌شده نیست؛ حتی پراکندگی صفر، یکتایی را ثابت نمی‌کند.

پیش‌شرط‌سازیِ پیش‌فرض یک تغییر مختصات مثبت‌معین و وارون‌پذیر روی تمام پارامترهای گره‌ای است؛ تعداد درجات آزادی را کم نمی‌کند. سپس tanh حد log-amplitude را اعمال می‌کند. گزینهٔ `precondition_shape=false` برای مقایسه و بازتولید مثال‌های توسعهٔ اولیه موجود است. هیچ چهار مود ثابتی انتخاب نمی‌شود.

## خروجی و استفادهٔ دوباره بدون بهینه‌سازی

- `fitted_model.json`: پارامترهای جواب انتخاب‌شده، تنظیمات و هش وزن و کدِ مدل مبنا.
- `candidate_parameters.npz`: پارامترهای تمام شروع‌ها و شمارهٔ جواب انتخاب‌شده.
- `reconstructed_flow.npz`: شبکهٔ x,y، میدان‌های u,v,p، میدان هر نامزد و پراکندگی آن‌ها.
- `inlet_normalized.csv` و `inlet_reference_units.csv`: پروفایل با میانگین یک و پروفایل در واحد مرجع.
- `track_*_forward.csv`: مسیر و سرعت ذرات از حل ODE مستقل؛ `track_*_integral_fit.csv`: تطبیق انتگرالی.
- `report.json`: خطای مسیرها، residual فیزیک، رتبهٔ حساسیت، وضعیت optimizer هر شروع، هش مدل و وضعیت تجربی.
- `problem.json` و CSVهای مشاهده: ورودیِ قابل اجرای دوباره در همان پوشه؛ `optimization.jsonl`: روند بهینه‌سازی.
- نقشه‌های جریان و نمودار مسیر/ورودی.

```python
import numpy as np
from flow_reconstruction.io import load_fit
model, theta = load_fit("runs/my_reconstruction/fitted_model.json",
                        "models/candidates/pressure_long/checkpoint.npz",
                        allow_unvalidated=True)
u_v_p = model.fields(theta, np.array([[1.0,0.5], [3.0,0.3]]))
```

بارگذاری جواب ذخیره‌شده، بهینه‌سازی یا آموزش را اجرا نمی‌کند. تغییر وزن یا کدِ تفسیرِ مدل، با گزارش قبلی بی‌سروصدا معتبر فرض نمی‌شود.

## مثال مستقل FEM و آزمون‌ها

```bash
python -m flow_reconstruction.demo --launch corners \
  --output runs/corner_demo --starts 3 --iterations 500
python -m pytest -q tests/test_reconstruction.py
```

در این مثال، دو مسیرِ زمان‌دار از میدان FEMِ Beta، با دو پرتاب گوشه‌ای و نویز موقعیت ساخته می‌شوند. میدان و ورودی حقیقی فقط برای **ارزیابی پس از استنتاج** خوانده می‌شوند؛ در مسئلهٔ معکوس فقط دو مسیر و اطلاعات پرتاب استفاده می‌شوند. نمونهٔ مستقل موجود در مخزن برای توسعهٔ این روش مصرف شده و آزمون کور نهایی نامیده نمی‌شود. دو مرجع رزروشدهٔ اصلی پروژه دست‌نخورده می‌مانند.

نتایج اجراشده، داده‌های ورودی و خروجی در [`examples/`](examples/) ذخیره می‌شوند. گزارش عددی و محدودیت‌ها در [RESULTS.md](RESULTS.md) آمده است. مسیرهای نمونه را می‌توان با CLI عمومی `reconstruct` هم دوباره اجرا کرد.
